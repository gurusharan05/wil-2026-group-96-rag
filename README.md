# International Student RAG — Seven Melbourne Universities, Five Courses

## 1. Project Overview

The **International Student Assistant** is a Retrieval-Augmented Generation (RAG) application that helps international students compare postgraduate courses at Melbourne universities and find reliable information about studying and working in Australia.

**Universities covered**

- RMIT University
- The University of Melbourne
- Monash University
- Deakin University
- La Trobe University
- Swinburne University of Technology
- Australian Catholic University (ACU)

**Courses covered** (where each university offers them)

| Course | Universities with a record |
|---|---|
| Master of Data Science | 7 |
| Master of Information Technology | 7 |
| Master of Cyber Security | 7 |
| Master of Artificial Intelligence | 6 (no Swinburne record) |
| Master of Business Analytics | 6 (no ACU record) |

**General Australian information:** student visa work conditions (Department of Home Affairs), workplace rights (Fair Work Ombudsman) and study information (Study Australia).

The application combines a structured course comparison with question answering grounded in source documents and generated by a local language model. Everything runs locally; no internet connection is needed once the models are downloaded.

> **What changed in version 2** (faster answers, correct fees for every university, evidence only from the university asked about, four new courses, automated tests): see [`CHANGES.md`](CHANGES.md).
> After pulling version 2, rebuild the knowledge base once: `PYTHONPATH=. python scripts/ingest_clean_v2.py`.

## 2. Main Features

### Compare Courses

Uses deterministic filtering over `data/structured/university_courses.csv` (33 course records).

- Choose a **course** (Data Science, IT, Business Analytics, Cyber Security, AI) and one or more **universities**.
- Each card shows the course name, course code, international fee, fee year and fee basis, duration, campus, intakes and a link to the official course page.
- If a fee is not published, the card says "See course page" instead of guessing.
- If a university has no record for the chosen course, the app says so.

Fees keep their published year and basis (annual, per 48 credit points, total course) because universities report them differently. They should not automatically be read as directly comparable annual fees.

### Ask a Question

1. The user types a question, e.g. *"What are the data science fees at RMIT?"*
2. **Question understanding:** the app finds the universities (using aliases such as "unimelb", "ACU", "latrobe"), the course (e.g. "IT", "cyber", "AI"), the topic (course, accommodation, work rights) and the facts requested (fee, duration, campus, intake, entry, English, course code, CRICOS). Matching uses whole words, so "current" is not read as "rent" and "coursework" not as "work".
3. **Filtered retrieval:** evidence is taken **only** from the named universities, course and topic.
   - Fact questions use a direct lookup of the structured course record (no embedding and no language model, so they answer almost instantly).
   - Other questions use semantic search in ChromaDB, filtered by university, course and topic, with a distance threshold to reject weak matches.
4. **Answering:** facts are answered directly from the structured record; comparisons become a table; open questions are answered by Qwen3 with thinking switched off, streamed word by word.
5. **Evidence:** only the sources actually used are shown, with the university, document, snapshot date and official link, plus the response time.

If no relevant evidence is found, the app says so instead of inventing an answer.

## 3. Technology Stack

| Component | Technology |
|---|---|
| Programming language | Python (3.9 or newer) |
| User interface | Streamlit |
| Large language model | Qwen3 14B (`qwen3:14b`) |
| Embedding model | Qwen3 Embedding 0.6B (`qwen3-embedding:0.6b`) |
| Language model runtime | Ollama (local) |
| Vector database | ChromaDB (collection `international_student_kb`) |
| Structured data processing | Pandas, csv |
| PDF / HTML text extraction | pypdf, BeautifulSoup |
| Testing | pytest, evaluation and benchmark scripts |

The language model and the embedding model are separate. The embedding model turns questions and document chunks into vectors for search; Qwen3 writes answers to open questions.

**Key settings (`config.py`):** chunk size 1,200 characters with 200 overlap (split on whole lines; structured records are never split), top-k 5, maximum distance 0.95, LLM `temperature 0`, `num_predict 600`, `num_ctx 4096`, model kept loaded for 30 minutes, `INDEX_VERSION = 3`.

- Python 3.9 or newer (3.11 recommended for a fresh environment)

- A computer with enough memory for `qwen3:14b` (`qwen3:8b` is a faster option; see section 15)

## 6. Installation and Setup

### Step 1 — Get the project

```bash
git clone https://github.com/gurusharan05/wil-2026-group-96-rag.git
cd wil-2026-group-96-rag
```

### Step 2 — Create and activate a virtual environment

```bash
python3 -m venv venv
source venv/bin/activate          # macOS / Linux
# venv\Scripts\activate           # Windows
```

Check that `which python` points to the project's `venv` folder.

### Step 3 — Install dependencies

```bash
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

### Step 4 — Check Ollama and the models

Make sure the Ollama app is running, then:

```bash
ollama list
```

If either model is missing:

```bash
ollama pull qwen3:14b
ollama pull qwen3-embedding:0.6b
```

## 7. Build the Knowledge Base

The raw documents and the structured course records are split into chunks, embedded and stored in ChromaDB. Run this from the project root the first time, and again whenever the source data, `config.py` registries or the ingestion script change:

```bash
PYTHONPATH=. python scripts/ingest_clean_v2.py
```

Expected summary:

```text
Raw files found: 50
Structured course records added: 33
Documents: 109
```

The script deletes and recreates the collection and prints a chunk count per university and category. Every university should appear under its own name (none listed as "Australia").

The app checks the index version. If the knowledge base was built by an older script, the app shows the rebuild command instead of giving wrong answers.

### Adding a university or course

- **University:** add a folder under `data/raw/`, add an entry to `UNIVERSITY_REGISTRY` in `config.py` (folder, official name, aliases), add rows to `university_courses.csv`, then rebuild.
- **Course:** add an entry to `COURSE_REGISTRY` in `config.py` (key, name, aliases), add rows to `university_courses.csv` with that `course_key`, add `course_<key>.pdf` snapshots (`scripts/make_course_snapshots.py` can generate them from the CSV), then rebuild.

## 8. Run the Application

With the virtual environment active and Ollama running:

```bash
python -m streamlit run app.py
```

Open the address printed in the terminal (usually `http://localhost:8501`). The first open question takes longer while the model loads; after that, the model stays loaded for 30 minutes.

Try:

- *What are the data science fees at RMIT?* (AUD 47,040, answered in about 0.0 s, RMIT evidence only)
- *Compare cyber security fees at Monash and Swinburne*
- *Which universities offer a Master of AI?*
- *How many hours can I work per fortnight on a student visa?*
- *What will I study in the RMIT Master of Data Science?* (an open question answered by Qwen3)

## 10. Evaluate Retrieval and Response Time

### Retrieval evaluation

```bash
PYTHONPATH=. python scripts/evaluate_retrieval.py
```

Uses the 36 questions in `data/structured/evaluation_questions.csv` (35 in-domain, 1 out-of-domain) and saves results under `evaluation/results/`.

| Metric | Meaning |
|---|---|
| Source Hit@1 / @3 / @5 | The expected university's source is in the top 1 / 3 / 5 results |
| Keyword Hit@k | The expected answer keywords appear in the top *k* results (numbers are normalised, so "57,984" matches "57984") |
| Combined keyword hit | All expected keywords appear across the retrieved results |
| Out-of-domain rejection | Unsupported questions return no evidence |

Team run on version 2: **in-domain Source Hit@5 97.1% (34/35)**, **Keyword Hit@5 88.6% (31/35)**, **out-of-domain rejection 100%**.

These metrics measure retrieval; they do not prove that every generated answer is correct.

### Response time

```bash
PYTHONPATH=. python scripts/benchmark_latency.py              # 3 runs per question
PYTHONPATH=. python scripts/benchmark_latency.py --repeats 5
```

Measures time per question type (fact, comparison, accommodation, work rights, open LLM question). Results go to `evaluation/results/latency_results.csv` and `latency_summary.csv`. Model loading is reported separately as warm-up time. Fact questions answer in about 0.00 s because they make no model call.

## 11. Automated Tests

```bash
python -m pytest tests/ -v
```

Expected: **73 passed**. Ollama is **not** needed: the tests use a stand-in for Ollama, build a temporary knowledge base and finish in seconds.

The tests check:

- university detection for all seven universities and their aliases, without mistaking "Melbourne" or "Australia" for a university;
- course detection (e.g. upper-case "IT" and "AI" only, so "is it online?" is not the IT course);
- topic detection on whole words;
- the correct fee for every university and for the new courses, with no other university's fee in the answer;
- that evidence comes only from the university and course asked about;
- that fact questions make no model calls, and that the LLM is called with `think=False`;
- that missing courses and unpublished fees are reported, not invented;
- ingestion labels, line-aware chunking, and that every course record has a snapshot PDF.

## 12. Source Data and Reliability

- Snapshots in `data/raw/` are **project-created PDFs** based on official university and Australian Government pages. They are not official publications. Each snapshot records its source URL and snapshot date, which are also listed in `source_manifest.csv`.
- Records added on 19 Oct 2026 (the IT, Business Analytics, Cyber Security and AI courses) carry a `verification_note` until the team has checked them against the official page.
- The La Trobe Master of Artificial Intelligence and Master of Business Analytics international fees were not published on the sources available, so the fee field is blank and the app says "See course page".

Before a final demonstration or deployment:

- Check course details against each university's official website.
- Check student visa conditions with the Department of Home Affairs.
- Check workplace rights with the Fair Work Ombudsman.
- Refresh time-sensitive fees, entry requirements, intakes and accommodation information, record the check date, then rebuild and re-evaluate.

This is an informational student project, not a substitute for official immigration, legal, financial or university advice.

## 13. Source Boundaries

| Information | Source used |
|---|---|
| Course and university information | The relevant university's official website (RMIT, Melbourne, Monash, Deakin, La Trobe, Swinburne, ACU) |
| Student visa work conditions | Australian Department of Home Affairs |
| Workplace rights and protections | Fair Work Ombudsman |
| General study and student-life information | Study Australia and official university pages |

University questions are only answered from that university's documents; work-rights questions are answered from government sources.

## 14. Development Workflow

1. Activate the virtual environment and pull the latest `main`.
2. Create a branch for your change.
3. Make the change; run `python -m py_compile app.py config.py rag.py`.
4. Rebuild the knowledge base if data, registries or ingestion changed.
5. Run `python -m pytest tests/ -v` and, for retrieval changes, the evaluation script.
6. Test the Streamlit app by hand.
7. Commit only your intended files and open a Pull Request into `main`.

### Git rules

Do not commit `venv/`, `data/chroma_db/`, `evaluation/results/`, `__pycache__/`, `.DS_Store`, backups, passwords or tokens (most are already in `.gitignore`). Never force-push or push directly to `main`; use `git add <file>` rather than `git add .`.

## 15. Limitations

- Answers depend on the quality and completeness of the snapshots.
- Fees and accommodation information change, and different fee years and bases limit direct comparison.
- Some new course records are still awaiting team verification; two La Trobe fees are unpublished.
- Open questions depend on the local model's speed. `qwen3:8b` can replace `qwen3:14b` in `config.py` for faster answers on smaller computers.
- Retrieval metrics do not guarantee answer correctness.
- The knowledge base covers only the included sources and is not refreshed automatically.

## 16. Future Improvements

- Verify all new course records and fill the missing La Trobe fees.
- Add more courses and universities (the registries in `config.py` make this a data task).
- Evaluate answer quality, not only retrieval, and compare Qwen3 8B with 14B on the same question set.
- Automate checking whether snapshots are out of date.
- Add conversation memory for follow-up questions.
